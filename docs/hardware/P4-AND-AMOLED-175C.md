# Waveshare P4 Knob and AMOLED 1.75C feature comparison

This comparison covers Dragon Detector 0.14.8 on the ESP32-P4-Knob-Touch-AMOLED-1.75X and the **32 MB ESP32-S3-Touch-AMOLED-1.75C**. The P4 application has SHA-256 `b92948c7d3ed2ee415089ee9d64d8fddcb85e47e2e92c6a4c63cd8f2ef2873e0`. The S3 column describes the implementation selected by the 1.75C build.

| Function | AMOLED 1.75C | P4 Knob |
| --- | --- | --- |
| Wi-Fi survey and channel display | The native radio supplies received frames. Channel Activity computes frame rate from frames and observed channel dwell time. | The SDIO driver returns AP records from completed passive surveys. Open **Evil → Wi-Fi Channel Visualizer** for AP counts and strongest RSSI by channel. One busy AP counts once. A blank survey and a failed survey have distinct states. |
| Bluetooth observation | BLE receiver feeds contact details, the advertisement notebook and the shared BLE tools. | **BLE Lab → Observed devices** uses real passive advertisements. **BLE Beacon Scan** counts recognized iBeacon and Eddystone reports. Each receive window keeps bounded data per address. Counts describe reports and can include repeats. |
| Detector profiles and radio selection | The native build provides the larger family and protocol-specific recon menu. | **Modes** offers Wi-Fi only, Bluetooth only and both. The separate **Detector profile** picker offers Dragon Radar, Axon Watch, ALPR Watch and Sky Watch. Sky Watch can inspect broadcast BLE fields. Its raw Wi-Fi Remote ID path is unavailable on the current P4 backend. A family match retains the confidence of its evidence. |
| Target selection and Hunt | Signal history and Hunt use selected contacts from the receive pipeline. | Hunt accepts recent Wi-Fi and BLE contacts. Choose **Hunt signal** in the contact details to track it directly. The nearby picker uses existing observations. |
| History, alert rules and SD event logging | Accepted contacts feed persistent history and the per-visit notification policy. The 1.75C has internal storage. | P4 observations use the shared history and watch-list rules. A new contact or change in evidence can be logged to SD when event logging is enabled. |
| Recon Notebook | The Wi-Fi frame notebook and BLE advertisement inspector have native receive producers. | Open **BLE Lab → Advertisement inspector** or **Inspect advertisement** in a BLE contact. The inspector reads the latest complete advertisement retained for that device and shows decoded fields, service UUIDs and bytes. Display privacy masks the raw payload. Wi-Fi probe requests require raw frames, which the P4 survey does not return. |
| Saved sessions and captures | Internal recon storage supports saved captures and recon sessions. | Existing files can be browsed on the TF card. New raw captures and recon missions are gated. A future AP/BLE survey session format could store time, RSSI and channel with an explicit unit. Such files would contain sightings rather than raw packets. |
| Nearby BLE address estimate | Uses signal samples and the measured BLE listening time to age entries. | The estimate is gated on the tested P4; an accurate port needs BLE-window duration and samples wired into the estimator. The normal BLE contact list works. |
| Clock, badge, timers and media | Shared watch faces, badge, stopwatch and locksport timer. The 1.75C uses USB or configured Wi-Fi clock recovery and has no TF slot. | Shared watch faces, badge, timers, PCF85063 RTC and TF storage. Voice Recorder and Music Library appear under **Utilities → Activity**. The knob has a microphone, speaker and headphone jack. End-to-end sound quality and jack switching require listening checks. |
| Raw Wi-Fi, CSI and node features | The S3 implementation has native Wi-Fi frames and CSI. Biscuit/JCMK node workflows use ESP-NOW. | The integrated P4 SDIO backend supplies surveys and BLE advertisements. Raw packet capture, frame-level traffic and probe observations, CSI Room Motion and ESP-NOW node mode remain gated. A different supported transport/API would require separate integration and testing. The companion silicon’s radio specification alone cannot establish support. |
| GPS wardrive | The 1.75C profile lacks the removable storage and GPS configuration of the non-C variants. | The P4 has TF storage. Its GPS wardrive start is gated and this build has no configured GPS provider. Observation-only SD event logging is a separate function. |

## Radar and evidence

The default radar shows enabled detector families with matching evidence. Named matches display the family and advertised name. **Settings → Radar** switches between candidates and all contacts. The Wi-Fi and Bluetooth lists show ordinary devices independently of that choice. The shared contact logic counts one AP sighting per completed survey and the received BLE reports per address window. Each retained BLE payload contributes one signature decision. Public AP addresses and advertised names use the same confidence rules across boards.

Host tests exercise unrelated and matching broadcasts, first-match history, repeat visits, saturated counts, logging cadence and contact labels at the actual display font size. Earlier image `e6b2035a` passed radio and standby checks but defaulted to all contacts and left the advertisement inspector empty.
